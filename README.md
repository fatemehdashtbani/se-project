# Routine Manager — Engineering Blueprint

This repository blueprint defines the engineering workflow, initial architecture, requirements baseline, delivery roadmap, and decision-record process for a professional online routine-management platform.

## Product direction

Build a routine-management platform where users create and track daily/weekly/monthly routines and habits, mentors support users with explicit revocable consent, and administrators operate subscription plans and platform governance. Web app for all roles; Android app for end users.

## Technology baseline

- Frontend (web): Vue 3, TypeScript, Vite, Vue Router, Pinia.
- Mobile (Android): to be decided in ADR-0004 (candidates: Flutter / React Native / Kotlin).
- Backend: Python, FastAPI, Pydantic, SQLAlchemy 2.x.
- Database: SQLite for local development and fast unit-level tests; PostgreSQL is the production database and the authoritative integration/time-zone-test database.
- Migrations: Alembic.
- API contract: versioned REST API under `/api/v1`, OpenAPI generated by FastAPI.
- Testing: TDD; pytest for backend, Vitest and Vue Test Utils for frontend, Playwright for end-to-end tests.
- Background jobs (MVP): FastAPI BackgroundTasks. A durable queue (e.g., Redis-backed) will be introduced via an approved ADR when scale demands.
- Initial deployment: a modular monolith. No Docker or Kubernetes for local development; do not introduce microservices without an approved ADR and measurable need.

## Documents

- `AGENTS.md`: mandatory instructions for AI coding agents and human contributors.
- `Task-List.md`: project-wide delivery queue and feature-intake gate.
- `docs/ARCHITECTURE.md`: architecture and technical design (SAD).
- `docs/SRS.md`: product requirements, roles, journeys, and acceptance criteria.
- `docs/ROADMAP.md`: phased delivery plan and release gates.
- `docs/adr/`: architecture decision records.
- `docs/templates/`: reusable feature and ADR templates.

## Non-negotiable workflow

No feature implementation starts until its task is registered in `Task-List.md`, its `SPEC.md` and `PLAN.md` exist, acceptance criteria are testable, and relevant ADRs have been recorded or explicitly deemed unnecessary. Follow Red → Green → Refactor.
